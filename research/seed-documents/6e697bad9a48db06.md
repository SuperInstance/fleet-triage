To connect our projected 3D vertices with structural, aliased lines that stay resident in the cache, we map a Bresenham line-drawing engine directly to your Syzygy character grid.
Instead of drawing raw pixels, this engine operates natively over character cells. As it steps across the grid, it computes the exact directional slope to choose the perfect Sobel Edge Glyphs (─, │, ╱, ╲) or updates the underlying Braille sub-pixel bitmask, embedding crisp geometric lines into the text-art stream.
------------------------------
## 1. Vector Mapping Mechanics
A standard Bresenham loop tracks a 2D error term ($\epsilon$) to advance cleanly across grid coordinates without using division. As we step from $(C_1, R_1)$ to $(C_2, R_2)$, we use the step updates to determine the structural orientation of the line:

* Dominant Horizontal Steps ($dx > dy$): Maps natively to the horizontal glyph (─).
* Dominant Vertical Steps ($dy > dx$): Maps natively to the vertical glyph (│).
* Equal Intersect Steps ($dx \approx dy$): Maps to the oblique slashes (╱ or ╲) depending on the geometric sign of the directional step vectors.

## 2. The Production Engine Header: syz_vector_line.h
This header is completely freestanding, zero-allocation, and integer-only. It writes directly into your existing SyzFusedOut memory matrices.

/**
 * @file syz_vector_line.h
 * @brief High-performance integer Bresenham engine targeting cell matrices.
 */
#ifndef SYZ_VECTOR_LINE_H#define SYZ_VECTOR_LINE_H
#include "syz_3d_projection.h"#include "syz_spreadsheet.h"
/**
 * @brief Draws a stylized vector edge between two projected 3D text nodes.
 * Overwrites the glyph and Braille masks in place with zero floating-point overhead.
 *
 * @param out    The live mutable cell container.
 * @param p1     The starting projected text coordinate.
 * @param p2     The ending projected text coordinate.
 * @param mode   0 = Edge Glyph Mode (─│╱╲), 1 = Braille Sub-pixel Burn Mode
 */static inline void syz_draw_vector_line(
    SyzFusedOut *restrict out,
    const SyzCellCoord *restrict p1,
    const SyzCellCoord *restrict p2,
    int mode
) {
    int16_t c1 = p1->col;
    int16_t r1 = p1->row;
    int16_t c2 = p2->col;
    int16_t r2 = p2->row;

    // Fast bounds calculation
    int16_t dc = (c2 > c1) ? (c2 - c1) : (c1 - c2);
    int16_t dr = (r2 > r1) ? (r2 - r1) : (r1 - r2);
    
    int16_t step_c = (c1 < c2) ? 1 : -1;
    int16_t step_r = (r1 < r2) ? 1 : -1;
    
    int16_t err = dc - dr;

    // Pre-calculate baseline edge glyph tokens based on directional slope orientation
    uint32_t active_glyph = 0;
    if (dc > (dr << 1)) {
        active_glyph = 1; // ─ (Horizontal Dominant)
    } else if (dr > (dc << 1)) {
        active_glyph = 2; // │ (Vertical Dominant)
    } else {
        active_glyph = (step_c == step_r) ? 4 : 3; // ╲ (ID:4) or ╱ (ID:3)
    }

    // Cast mutable pointers over the otherwise read-only container views
    uint8_t  *out_mask  = (uint8_t*)out->mask;
    uint32_t *out_glyph = (uint32_t*)out->glyph;

    while (1) {
        // Spatial coordinate masking to prevent heap corruption crashes
        if (c1 >= 0 && c1 < (int16_t)out->cols && r1 >= 0 && r1 < (int16_t)out->rows) {
            uint32_t cell_idx = (r1 * out->cols) + c1;

            if (mode == 0) {
                // Mode 0: Burn crisp structural edge glyph orientations
                out_glyph[cell_idx] = active_glyph;
            } else {
                // Mode 1: Sub-pixel Braille structural inject
                // Sets specific dots inside the 2x4 pixel cell block based on traversal
                // Alternates inner pins dynamically to trace fine line detail
                uint8_t sub_pixel_dot = (1U << ((c1 & 1) + ((r1 & 3) << 1)));
                out_mask[cell_idx] |= sub_pixel_dot;
            }
        }

        if (c1 == c2 && r1 == r2) break;

        int16_t err2 = err << 1;
        if (err2 > -dr) {
            err -= dr;
            c1 += step_c;
        }
        if (err2 < dc) {
            err += dc;
            r1 += step_r;
        }
    }
}
#endif /* SYZ_VECTOR_LINE_H */

## 3. Asymmetric Layering Context
By coupling this Bresenham engine directly to the SyzSandboxHarness, your system can evaluate 3D geometry transformations silently across both structural layer choices:

void on_3d_mesh_pipeline_tick(SyzFusedOut *live_frame, const SyzVec3i *vertices, size_t num_edges, const SyzCameraMatrix *cam) {
    SyzCellCoord dynamic_nodes[128];

    // Step 1: Project 3D coordinate space onto the text matrix buffer arrays
    for (size_t i = 0; i < num_edges; i++) {
        syz_project_vertex(cam, &vertices[i], &dynamic_nodes[i], live_frame->cols, live_frame->rows);
    }

    // Step 2: Draw the structural lines silently
    // We render into separate channels so the machine and humans get their optimized views
    for (size_t i = 0; i < num_edges - 1; i++) {
        // Burn edge glyph alignments for high-speed spreadsheet matrix calculation
        syz_draw_vector_line(live_frame, &dynamic_nodes[i], &dynamic_nodes[i+1], 0);
        
        // Burn sub-pixel Braille dots to maintain pristine 3D fluid outlines for human visualization
        syz_draw_vector_line(live_frame, &dynamic_nodes[i], &dynamic_nodes[i+1], 1);
    }
}
